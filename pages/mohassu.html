MohaSSU | Android·Firebase 개발

Firebase 인증과 사용자 데이터를 Android 화면에 연결하고, 친구 관계·시간표·현재 수업 확인 기능을 개발했습니다.

프로젝트 소개

MohaSSU는 친구의 프로필과 시간표를 확인하고 지도·약속 기능을 이용하는 Android 앱입니다. 회원가입·프로필 입력부터 시간표 저장, 친구 목록·검색·현재 수업 표시까지 화면과 데이터 연동을 담당했습니다.

내가 담당한 부분

  • 가입·프로필: Firebase 인증, 이메일 인증, 프로필 입력·저장·조회.
  • 시간표: 마이페이지의 시간표 저장·조회·수정, 친구 시간표 확인.
  • 친구 관리: 이메일 기반 추가, 목록·검색, 프로필 바텀시트, 삭제 관련 수정.
  • 상태 표시: 현재 요일·시각과 시간표를 비교해 진행 중 수업 표시.
  • 기타: Firestore 전환, 알림 목록·RecyclerView, 지도 SDK 추가 관련 작업.

친구 관계의 양방향 저장과 예외 처리

기존 구조

친구 추가 로직이 상대방의 위치 문서 조회와 연결되어 있었고, 관계 저장은 본인 친구 목록을 중심으로 처리했습니다.

변경

이메일로 대상 사용자를 찾은 뒤 자기 자신인지, 이미 친구로 등록했는지 확인하도록 수정했습니다. 내 친구 목록에는 상대 UID를, 상대 친구 목록에는 내 UID를 저장하고, 없는 사용자와 저장 실패 상황을 안내하도록 했습니다.

결과

양쪽 계정의 친구 관계를 생성하는 흐름과 자기 자신·중복 등록을 방지하는 분기를 추가했습니다.

남은 과제

두 관계 저장은 독립적인 비동기 호출입니다. 한쪽만 성공하는 상황에 대비한 일괄 쓰기와 오류 복구는 개선 대상으로 남아 있습니다.

친구 관계 수정 전후(새 탭에서 열림)

시간표를 활용한 친구의 현재 수업 표시

해결할 과제

친구 목록에서 프로필과 함께 현재 진행 중인 수업을 확인할 수 있어야 했습니다.

구현

친구 UID로 Firestore의 프로필과 시간표를 조회했습니다. 현재 요일·시·분을 수업 시작·종료 시각과 비교해 해당 수업을 찾고, 그 결과를 친구 객체에 포함해 RecyclerView에 표시했습니다. 친구 선택 시 프로필 바텀시트를 열고, 검색어 변화에 따라 목록을 필터링했습니다.

결과

프로필·시간표 조회 결과를 하나의 친구 목록 화면에 연결했습니다. 현재 수업은 화면에서 데이터를 조회한 시점을 기준으로 판별합니다.

현재 수업 표시(새 탭에서 열림) · 친구 검색(새 탭에서 열림)

회원가입·프로필·시간표의 Firebase 연동

해결할 과제

인증된 계정과 앱에서 사용하는 프로필·시간표 데이터를 연결하고, 여러 화면에서 저장·조회할 수 있어야 했습니다.

구현

Firebase Authentication으로 사용자 인증과 이메일 인증을 처리하고, UID를 기준으로 Firestore 사용자 정보에 접근했습니다. Realtime Database에서 Firestore로 연동 코드를 변경하며 회원가입 화면·프로필 ViewModel을 수정했습니다. 마이페이지에는 시간표 저장·불러오기·수정 흐름을 연결했습니다.

결과

계정 인증과 앱 데이터를 연결하고, 사용자 정보와 시간표를 화면에서 저장·조회하는 기능을 구현했습니다.

Firestore 전환(새 탭에서 열림) · 이메일 인증 후 이동(새 탭에서 열림) · 시간표 저장(새 탭에서 열림)

화면 흐름과 수정 경험

  • 가입 화면: 인증 계정 생성·이메일 인증·추가 정보 입력 흐름을 연결.
  • 친구 화면: 관계 목록 → 프로필·시간표 조회 → 목록 표시 → 프로필 바텀시트.
  • 시간표 화면: 저장·DB 반영·조회 화면 이동 관련 코드 수정.

시간표 저장 버튼에서 저장 함수를 호출한 뒤 화면 이동을 추가하고, 마이페이지 시간표 표시 관련 코드를 수정했습니다. 저장 완료 전 화면 전환과 저장 실패 처리는 후속 검증 항목입니다.

저장 화면 이동 수정(새 탭에서 열림) · 시간표 표시 수정(새 탭에서 열림)

결과와 개선 방향

인증·프로필 입력, 시간표 저장·조회, 친구 추가·검색·현재 수업 표시를 화면과 연결했습니다. 후속 개선에서는 데이터 일관성과 비동기 처리의 실패 상황을 우선 다룰 수 있습니다.

  • 양방향 데이터 일관성: 친구 관계 저장을 일괄 처리하는 방식 검토.
  • 저장과 화면 이동: DB 저장 성공 후 이동하고 실패 시 안내·재시도 제공.
  • 조회·렌더링: 친구별 개별 조회와 화면 갱신 횟수를 줄이는 방안 검토.
  • 테스트: 현재 수업 판별을 별도 로직으로 분리해 시작·종료 시각과 빈 시간표 검증.
