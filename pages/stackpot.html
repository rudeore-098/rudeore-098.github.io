STACKPOT | 백엔드 개발·배포 자동화

프로젝트 소개

STACKPOT은 팟 단위의 팀 활동, 피드, 작업·일정 관리 기능을 제공하는 서비스입니다. 백엔드에서 회원 인증과 가입 흐름, 피드·Task API를 담당하고 Docker·GitHub Actions 기반 배포 설정을 구현·개선했습니다.

내가 담당한 부분

  • 인증·회원 관리: 카카오 소셜 로그인, JWT 발급·검증, Redis 기반 토큰 처리, 가입·로그아웃·탈퇴.
  • 가입 상태 분리: TempUser 도입, 사용자 유형별 인증 처리, 미완료 가입 데이터 정리.
  • 서비스 API: 피드 CRUD·좋아요, Task 생성·조회·수정·삭제, 월·일별 일정 조회.
  • 개발·배포 기반: 공통 응답·예외 처리, API 문서 보완, 사용자 서비스 테스트, Docker CI/CD 설정.

임시 회원과 정식 회원을 구분하는 인증 구조

과제

소셜 인증 이후 추가 정보를 입력하는 가입 흐름에서, 가입 중인 사용자와 가입을 마친 사용자를 구분해 처리해야 했습니다.

구현

TempUser 엔티티를 도입하고 토큰의 사용자 유형에 따라 인증 처리를 분기했습니다. TEMP 유형은 임시 회원 저장소에서 사용자를 조회하고 ROLE_TEMP 권한을 부여하도록 구성했습니다. 정식 회원의 사용자 조회·토큰 생성 관련 코드도 함께 수정했습니다.

결과

가입 진행 상태를 별도 데이터 모델과 인증 정보로 표현했습니다. 가입 중 사용자와 정식 회원을 구분하는 기준을 서버에서 다룰 수 있도록 변경했습니다.

GitHub 커밋 기록: [REFACTOR] TempUser 생성(새 탭에서 열림) · [REFACTOR] 토큰 생성 구조 변경 및 시큐리티 전면 수정(새 탭에서 열림)

가입 중도 이탈 데이터 정리

가입이 완료되지 않은 임시 회원을 정리하기 위해 매 정시에 실행되는 스케줄러를 구현했습니다. 생성 시각이 한 시간 이전인 TempUser를 트랜잭션 안에서 삭제하도록 구성했습니다. 정확히 생성 60분 후 삭제하는 TTL 방식이 아니라 주기적으로 대상 데이터를 조회·삭제하는 방식입니다.

GitHub 커밋 기록: [FEAT] TempUser 중도이탈 시 db 삭제(새 탭에서 열림)

서버 저장 상태를 확인하는 토큰 재발급

과제

재발급 요청에서 토큰 자체의 유효성과 서버에 등록된 토큰인지를 함께 확인해야 했습니다.

구현

Refresh Token을 검증한 뒤 Redis 저장 여부를 검사하고 사용자 정보를 조회했습니다. 재발급 서비스에서는 기존 Refresh Token을 삭제하고 새 토큰 발급 메서드를 호출합니다.

결과

유효한 JWT인지 검사하는 흐름에 서버 저장 상태 확인을 연결했습니다. 로그아웃과 재발급에 필요한 토큰 관리 로직을 개발했습니다.

GitHub 커밋 기록: [FEAT] refreshtoken을 통한 재발급, redis사용(새 탭에서 열림) · TokenService.java(새 탭에서 열림)

활성 서버에 따라 배포 대상을 선택하는 자동화

과제

Blue/Green 구성에서 현재 서비스 중인 서버를 확인하고, 반대편 컨테이너에 새 버전을 배포하는 절차가 필요했습니다.

구현

GitHub Actions에서 Nginx의 활성 포트를 읽어 배포 대상을 선택했습니다. Docker 이미지를 빌드하고 Docker Hub로 전달한 뒤, EC2에서 대상 컨테이너를 갱신하고 서버 전환 스크립트 switch_backend.sh를 호출하도록 구성했습니다. 배포 실행 기준을 main 브랜치로 변경하는 작업도 수행했습니다.

결과

활성 포트 확인, 배포 대상 선택, 이미지 전달과 컨테이너 갱신을 workflow로 연결했습니다. 무중단 여부와 롤백 동작은 운영 로그를 확보한 뒤 성과로 추가할 예정입니다.

GitHub 커밋 기록: [CI/CD] 무중단 배포(Blue/Green) 구축 및 자동화 설정 + 환경변수 관리 방식 개선(새 탭에서 열림) · [REFACTOR] cicd 수정 및 gitignore 설정(새 탭에서 열림)

서비스 API와 검증

피드 작성·조회·수정·삭제·좋아요와 Task 관리 API를 개발했습니다. 월·일 기준 일정 조회, 화면에 필요한 응답 필드, 잘못된 팟 정보 등에 대한 예외 처리를 보완했습니다.

GitHub 커밋 기록: [FEAT] my pot task 수정 / 삭제 / 자세히 보기 구현(새 탭에서 열림) · [FEAT] task 월,일에 해당하는 task 보기 api 구현(새 탭에서 열림)

사용자 서비스에는 기존 사용자·신규 사용자·닉네임 저장 시나리오의 테스트가 있으며, 헬스 체크 컨트롤러 테스트도 작성·수정했습니다.

GitHub 커밋 기록: UserCommandServiceImplTest.java(새 탭에서 열림)

개선 방향

  • 회원 상태 검증: 가입 완료 시 임시 토큰 처리와 임시 회원 접근 범위를 통합 테스트로 확인.
  • 재발급 동시성: 동일 Refresh Token으로 동시에 요청했을 때의 처리 정책과 원자성 검토.
  • 배포 검증: 테스트 통과 조건, 헬스 체크, 전환 실패 시 롤백 절차를 명시하고 실행 기록 확보.
