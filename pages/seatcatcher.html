프로젝트 소개

SeatCatcher는 지하철에서 좌석을 양보하려는 사용자와 자리가 필요한 사용자를 연결하는 모바일 서비스입니다. 백엔드에서 사용자 신고, 이용 경로 기록, 상황별 푸시 알림과 알림함을 담당했습니다.

내가 담당한 부분

  • 신고 API: 신고 생성·조회·수정·삭제, 본인 신고 조회와 신고자·피신고자 검증.
  • 경로 이력 API: 출발역·도착역 기반 이력 생성, 단건 조회·삭제와 커서 기반 목록 조회.
  • FCM 연동: 사용자 토큰 등록, 서버 인증, 메시지 구성·전송과 오류 처리.
  • 사용자 알림함: 유형·읽음 여부 필터, 목록·단건 조회·삭제, 읽음 처리.
  • 품질 관리: 신고·경로·알림 서비스 테스트, API 문서, Firebase 인증 파일 관련 배포 설정.

경로 이력과 알림의 커서 기반 목록 조회

과제

사용자의 경로 이력과 알림 목록을 일정 개수씩 이어서 조회하고, 앱에서 다음 목록의 존재 여부를 판단할 수 있어야 했습니다.

구현

마지막으로 조회한 ID와 요청 크기를 받아 다음 목록을 조회했습니다. size + 1개를 가져와 추가 항목 유무로 다음 페이지 존재 여부를 판단하고, 응답 목록과 커서를 구성했습니다. 페이지 처리 로직은 ScrollPaginationCollection으로 분리해 경로 이력과 알림 조회에 사용했습니다.

결과

앱의 무한 스크롤에 필요한 목록·커서 응답을 구현했습니다. 알림 목록에는 유형과 읽음 여부 필터도 연결했습니다.

GitHub 커밋 기록: [FEAT] 특정 pathHistory 삭제 및 무한 스크롤링 구현(새 탭에서 열림)

상황별 푸시 발송과 알림함 연결

과제

좌석 요청·수락·거절 등 상황마다 다른 메시지를 전달하고, 사용자가 앱 안에서 알림을 다시 확인할 수 있어야 했습니다.

구현

알림 유형별 제목·본문 템플릿을 Enum으로 관리하고, 공통 발송 메서드에서 필요한 인자를 채워 FCM 요청을 만들었습니다. 사용자 FCM 토큰을 저장하고 Google Credentials로 서버 인증 토큰을 발급받아 RestClient로 메시지를 전송했습니다. FCM 오류는 예외 코드로 처리하고 알림 이력 저장 로직을 연결했습니다.

결과

상황별 알림 메서드와 메시지 템플릿을 구성하고, 알림 목록·단건 조회·읽음 처리·삭제 API를 제공했습니다. 저장 모델은 사용자당 FCM 토큰 하나를 관리합니다.

GitHub 커밋 기록: [FEAT] 상황별 푸시알람 기능 구현(새 탭에서 열림)

개인 기록의 소유권 검증과 예외 테스트

과제

로그인한 사용자라도 다른 사람의 경로 이력과 알림을 조회·삭제할 수 없어야 했습니다.

구현

단건 조회·삭제 시 인증된 사용자와 데이터 소유자를 비교하고, 일치하지 않으면 접근 권한 예외를 발생시키도록 했습니다. 경로 이력 서비스에는 타 사용자 접근 시 예외가 발생하는 테스트를 작성했습니다.

결과

사용자 인증 이후 개별 데이터에 대한 접근 제한을 추가했습니다. 정상 조회뿐 아니라 권한이 없는 요청도 테스트 대상으로 포함했습니다.
